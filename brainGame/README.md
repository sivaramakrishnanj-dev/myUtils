# Brain Game

An Android brain trainer for filling bored minutes usefully. One puzzle at a
time, generated by Claude, pitched just above your current level, with a real
explanation when you get it wrong.

## How it works

Two things are deliberately kept apart:

- **The app decides what to serve.** A local Elo engine (`domain/Rating.kt`)
  rates you separately in five skills and picks the next skill and difficulty.
  No model call is involved — it is instant, offline, and cheap.
- **The model writes the content.** Claude generates the puzzle text and, on a
  failure, the explanation. It never decides whether your answer was right.

Correctness is always graded locally by `AnswerChecker`, and every generated
puzzle is structurally checked by `PuzzleValidator` before it reaches the
screen. A puzzle that fails validation is regenerated once rather than shown.

## The play loop

```
Bored → New puzzle
   ↓
Elo picks skill + difficulty, theme rotates      (local, instant)
   ↓
One Messages API call, structured JSON output     (~10-30s, Opus 5 thinks)
   ↓
Validate → save to Room as the ACTIVE puzzle
   ↓
Play. Every keystroke and hint is persisted, so pausing loses nothing.
   ↓
Solved / failed → Elo updates → explanation on failure
```

Exactly one puzzle is `ACTIVE` at a time. Closing the app mid-puzzle and
returning a week later resumes it exactly as left, because progress lives in
Room rather than in memory.

## Design decisions worth knowing

**One puzzle per request, no batching or pool.** The app is used in short bursts,
so a background pre-generation pipeline would add real complexity to save a wait
that only happens when you actually want a puzzle. The cost is that generation
latency is user-visible — mitigated with `effort: medium` and an honest
"this takes 10-30 seconds" message rather than a spinner that looks stuck.

**Abandoning a puzzle is rating-neutral.** There is no opponent to protect a
rating from, and being interrupted shouldn't cost anything. Abandons are still
counted, so a habit of rerolling away from hard puzzles would be visible.

**Partial credit on solves.** A solve after three hints and four wrong guesses
scores 0.35 rather than 1.0, so the rating tracks what you can do unaided.

**Structured outputs instead of parsing prose.** `output_config.format` with the
schema in `ai/PuzzleSchema.kt` guarantees the reply is valid JSON in the right
shape, so there is no text extraction to go wrong. Cross-field rules the schema
can't express (an answer index inside `options`, an ordering that is a real
permutation) are enforced by `PuzzleValidator`.

**The generation prompt is long and cached.** It carries calibration guidance
that is the main lever on puzzle quality, and it is sent with `cache_control`,
so back-to-back puzzles in one session re-read it at ~10% of input price. Keep
it byte-identical between calls — anything varying (skill, theme, difficulty)
goes in the user turn, never the system prompt.

**Effort is split by call type.** Generation runs at `medium` (validated
anyway, and you are waiting); explanation runs at `high`, because that is the
actual teaching moment.

**Themes are yours to define.** Five ship as built-ins, and you can add any
interest as free text in Settings — "Carnatic music", "Kubernetes", whatever.
Added themes are enabled immediately and persist across restarts. Your own
themes can be deleted; built-ins can only be toggled off, so the list can never
be emptied. A theme is only a setting for the puzzle, never a knowledge
requirement, so adding an obscure interest doesn't make puzzles unsolvable.

## Model and cost

Defaults to `claude-opus-5`, overridable in Settings and persisted. At Opus 5
pricing a puzzle is roughly 3-6¢ and an explanation similar, so a bored
half-hour costs well under a dollar. Switch to Sonnet 5 or Haiku 4.5 in Settings
if that ever matters.

## Setup

1. Open in Android Studio, or build from the command line.
2. Launch the app, go to **Settings**, paste an Anthropic API key, and Save.
3. **Play → New puzzle.**

```bash
./gradlew :app:testDebugUnitTest   # 36 tests, no device needed
./gradlew :app:assembleDebug
./gradlew :app:installDebug        # with an emulator or device attached
```

## Layout

```
domain/     Pure Kotlin, no Android deps — Elo, skill selection, validation,
            answer checking. This is where the unit tests point.
ai/         Anthropic Messages API client, JSON schema, prompts, generation
            and explanation services.
data/       Room entities, DAOs, and GameRepository — the only writer of
            ratings and the owner of the one-active-puzzle invariant.
settings/   DataStore-backed config (API key, model, themes, editable prompts).
ui/         Compose screens: play, stats, settings.
```

## Status

Working end to end: generation, all four answer input types, hints, resume,
Elo updates, explanations, stats, and custom themes. 45 unit tests cover the
rating engine, validation, answer grading, the JSON schema contract, and theme
config. Verified on an API 35 emulator, including the API error path and
add/remove/persist for custom themes.

Ideas not yet built: themed Sudoku and logic grids with constraint solvers
(needs a deterministic generator, not just a validator), prefetching one puzzle
ahead so "New puzzle" is instant, and a weekly review summarising where you
improved.
