# Review: Design — ADRs 0001–0004 (combined) — round 1

**Scope:** four Architecture Decision Records covering the principal technology choices invoked by `02-architecture.md`:
- ADR 0001 at `f44e681` — ANDROID InnerTube client
- ADR 0002 at `bae8a87` — OkHttp for HTTP
- ADR 0003 at `278f51f` — ffmpeg via ProcessBuilder
- ADR 0004 at `1d10c7c` — Jackson for InnerTube JSON parsing

Reviewed as a set because the four decisions are interdependent and reinforce each other: ADR 0001 picks the InnerTube client whose JSON Jackson parses (ADR 0004) over HTTP that OkHttp transports (ADR 0002), with muxing delegated to ffmpeg out-of-process (ADR 0003). A reviewer would push back on one by pushing back on the others.

---

## Review notes

No blocking, major, minor, or nit comments. All four ADRs approved as-drafted.

**What was verified across the set:**

- **Each ADR follows the template** (`adr/0000-template.md`): Status / Date / Deciders / Tags / Context / Decision / Alternatives considered (≥2 with one-paragraph rationale each) / Consequences (positive, negative, neutral) / References.
- **Alternatives are genuine, not strawmen.** Each ADR lists real competitors that a reasonable engineer might pick instead — JDK `HttpClient` and Apache HttpClient 5 in 0002, JavaCV / JCodec / bundled ffmpeg / no-mux in 0003, Gson and Jakarta JSON-P/B in 0004. Each alternative's rejection is a trade-off, not a dismissal.
- **Consequences are honest about costs.** 0002 calls out the ~800 KB + kotlin-stdlib cost. 0003 calls out "user must `brew install ffmpeg`". 0004 calls out ~2 MB and the Jackson CVE history. 0001 calls out "tool breaks when YouTube deprecates our client version" as expected and captured in OQ-A.
- **Sequential numbering, no gaps, no reuse** (0001 → 0002 → 0003 → 0004). Every ADR file is present on `origin/main`. `design/README.md` ADR index has all four entries marked Accepted.
- **Placeholder sweep complete.** All four `[ADR-NNNN — pending]` placeholders in `02-architecture.md` were rewritten to live markdown links in the same commit as the ADR they reference. No orphan placeholders remain; the only lingering "pending" string in `02-architecture.md` is the meta-note at line 16 explaining the convention, which is intentional documentation.
- **Cross-references among ADRs** — 0001 cites the yt-dlp community tooling it intentionally simplifies; 0002 references ADR 0001 as the boundary it talks to; 0003 references ADR 0001 as the reason we receive separate streams needing muxing; 0004 references ADRs 0001 and 0002 for the response shape and the transport. The four ADRs form a connected set, each self-contained but aware of its neighbours.
- **Fat-jar tally is credible.** OkHttp+Okio+kotlin-stdlib ~1.3 MB (ADR 0002) + Jackson family ~2 MB (ADR 0004) + picocli ~400 KB + SLF4J ~80 KB ≈ 3.8 MB of runtime deps, plus our own classes. On track for the ~5 MB target claimed in ADR 0001's consequences.
- **Three pre-flagged reviewer-push-points** (ADR 0002 OkHttp 4.x vs 5.x, ADR 0004 Jackson vs Gson fat-jar cost, ADR 0003 bundled-ffmpeg temptation) were acknowledged during draft preparation and accepted as-drafted. Legitimate targets for individual ADR `-r2` rounds if implementation experience forces a revisit.

**Why this review has no numbered comments:**

Silence in a review process must be explicit. This file exists to record that all four ADRs were reviewed, considered complete, and approved as-drafted — not that review was skipped. Future contributors challenging any of these decisions can trace their approval to commits `f44e681`, `bae8a87`, `278f51f`, `1d10c7c` via this review file.

**Gate:** ADRs 0001–0004 are **Accepted**. The technology stack invoked by `02-architecture.md` is frozen for MVP. Changes to any of the four decisions require a new ADR that supersedes the earlier one (never edit in place beyond status transitions and typo fixes). Proceeding to `03-data-model.md`.
