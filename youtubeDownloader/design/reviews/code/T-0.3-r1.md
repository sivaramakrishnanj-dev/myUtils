## P1 — Consistent versionless child pattern

- **Location:** `yt-cli/pom.xml:14–26` — all three `<dependency>` entries
- **Severity:** Praise
- **Category:** Reuse
- **Reviewer comment:**
  All three dependencies (`yt-core`, `picocli`, `slf4j-simple`) are declared versionless in the child, inheriting from the parent's `<dependencyManagement>`. This matches the pattern established in T-0.2 for `yt-core/pom.xml` and keeps version governance in a single place. Clean Code (Martin) — DRY on version strings.

## P2 — Scope-tight dependency set

- **Location:** `yt-cli/pom.xml` (entire file)
- **Severity:** Praise
- **Category:** Readability
- **Reviewer comment:**
  The child declares exactly the three deps the task requires — no test deps (deferred to T-0.5/T-0.7 per tester note), no plugins (shade is T-0.4, JaCoCo is T-0.6, Surefire is T-0.7). Excellent scope discipline for a scaffolding task.

## P3 — yt-core version via `${project.version}`

- **Location:** `pom.xml:76` — `<version>${project.version}</version>` on the yt-core managed dep
- **Severity:** Praise
- **Category:** Correctness
- **Reviewer comment:**
  Using `${project.version}` for the internal module dependency ensures yt-core and yt-cli always build at the same version. Eliminates a class of "forgot to bump the sibling version" bugs in multi-module Maven projects.

## N1 — Missing `<relativePath>` in child parent block

- **Location:** `yt-cli/pom.xml:6–10` — `<parent>` block
- **Severity:** Nit
- **Category:** Readability
- **Reviewer comment:**
  Same observation as T-0.2 m1: Maven defaults `<relativePath>` to `../pom.xml`, which is correct here. Adding it explicitly is self-documenting and avoids the Maven 4.x deprecation warning. Consistent with yt-core's current state (also omitted), so not a blocker — author's call whether to add it to both in a future cleanup.
- **Suggested fix:**
  ```xml
  <parent>
      <groupId>com.srk.myutils.yd</groupId>
      <artifactId>youtube-downloader</artifactId>
      <version>1.0.0</version>
      <relativePath>..</relativePath>
  </parent>
  ```
