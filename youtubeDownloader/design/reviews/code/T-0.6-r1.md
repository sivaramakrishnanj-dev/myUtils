## C2 — BUNDLE scope is correct for the NFR

- **Location:** `yt-core/pom.xml:85` (`<element>BUNDLE</element>`)
- **Severity:** Praise
- **Category:** Spec-Adherence
- **Spec citation:** NFR-UNIT-TEST-COVERAGE-MINIMUM: "80% line coverage **on the library module**"
- **Reviewer comment:**
  The NFR says "on the library module" — this maps to JaCoCo's `BUNDLE` element, which aggregates coverage across all classes in the module. One class can compensate for another, which is the intended flexibility.

## C3 — `check` goal bound to `verify` phase vs NFR text "during `mvn test`"

- **Location:** `yt-core/pom.xml:79` (`<phase>verify</phase>` on the `check` execution)
- **Severity:** Minor
- **Category:** Spec-Adherence
- **Spec citation:** NFR-UNIT-TEST-COVERAGE-MINIMUM: "Enforced by JaCoCo during `mvn test`."
- **Reviewer comment:**
  The NFR literally says "Enforced by JaCoCo during `mvn test`." The `check` goal is bound to the `verify` phase, which means `mvn test` (the project's `test_command`) does NOT trigger the coverage gate — only `mvn clean verify` (the project's `build_command`) does. Strictly read, this is a spec deviation.

  However, this is standard JaCoCo practice. The `check` goal requires the execution data file produced by `prepare-agent` + the test run. Binding `check` to the `test` phase is technically possible but fragile — it depends on plugin execution ordering within the same phase, and Maven does not guarantee ordering across plugins in the same phase. The `verify` phase is the canonical binding for `jacoco:check` per the JaCoCo documentation.

  The project's `build_command` is `mvn clean verify`, which is the gating command for every commit (per `spec-driven.yaml`). The coverage gate WILL fire on every commit. The NFR text "during `mvn test`" is an imprecision in the spec, not a code bug.

  **Verdict:** Accepted as-is. This is a Minor for documentation awareness, not a blocker. The tester's concern is resolved: the `verify`-phase binding is correct. If the spec author wants to tighten the language, they can update the NFR text to say "during `mvn verify`" in a future NFR review round.
- **Suggested fix:** (Optional, for spec maintainer) Update NFR-UNIT-TEST-COVERAGE-MINIMUM text from "Enforced by JaCoCo during `mvn test`" to "Enforced by JaCoCo during `mvn verify`" in a future requirements review round.
