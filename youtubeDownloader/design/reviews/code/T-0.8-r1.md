## Deviation ruling: Enforcer → SecurityManager

The task title says "Add Enforcer rule" but the implementer used a `SecurityManager`-based JUnit 5 auto-extension instead. This is **accepted** per Hard Rule 6 (spec is authoritative over task text):

- **AC-11.3** requires: "The test suite SHALL fail its default run (`mvn test`) if any unit test makes a network call."
- **AC-11.4** requires: "the test SHALL fail with a clear message naming the component that reached out."

Maven Enforcer is a build-time plugin that checks POM rules (dependency convergence, banned dependencies, etc.). It cannot detect runtime socket operations inside test code, and it cannot produce a per-test failure message naming the offending component. A `SecurityManager` installed via a JUnit 5 global extension intercepts `checkConnect`/`checkListen` at runtime, fails the offending test immediately, and includes the target host in the exception message — satisfying both ACs.

The task text "Enforcer rule" was a poor shorthand by the task author. The implementer's deviation is well-justified and documented in the Javadoc. Future readers: the artifact is a SecurityManager extension, not a Maven Enforcer rule.

## C2 — DNS intercept message shows `port=-1` — acceptable per Java semantics

- **Location:** `NoNetworkExtension.java:53` — `checkConnect(String host, int port)`
- **Severity:** Nit
- **Category:** Spec-Adherence
- **Spec citation:** AC-11.4 — "fail with a clear message naming the component that reached out"
- **Reviewer comment:**
  When `InetAddress.getByName("example.com")` triggers DNS resolution, the JVM calls `SecurityManager.checkConnect("example.com", -1)` — the `-1` port is Java's internal convention for DNS lookups (see `SecurityManager` Javadoc). The resulting message reads: `"Unit test attempted network connection to example.com:-1"`. The tester flagged this as potentially unclear.

  **Ruling:** AC-11.4 requires the message to "name the component that reached out." The host (`example.com`) is present and clearly identifies the component. The `:-1` suffix is a Java platform artifact, not an implementer choice. Changing it would require special-casing `port == -1` in `checkConnect` to produce a different message template (e.g., "DNS lookup for example.com"). This is a cosmetic improvement, not a spec violation. The current message satisfies AC-11.4.
- **Suggested fix:** Author's call. If desired, a future task could special-case `port == -1` to say "DNS lookup for" instead of "connection to". Not required for this task.

## C3 — No `AfterAllCallback` to restore original SecurityManager — acceptable

- **Location:** `NoNetworkExtension.java:36-40` — `beforeAll` installs but never restores
- **Severity:** Nit
- **Category:** Discussion
- **Reviewer comment:**
  The extension installs a `SecurityManager` in `beforeAll` and never restores the original (which is `null` by default). For a Surefire-scoped JVM that exits after tests, this is fine — there is no "after" that needs the original manager. The `installed` volatile guard prevents redundant re-installation across test classes.

  If the project ever moves to a test framework that reuses JVMs across modules (e.g., Gradle's `--daemon` with `forkEvery=0`), this would need revisiting. Maven Surefire forks a fresh JVM per module by default, so this is safe today.
- **Suggested fix:** None required. Document the assumption in a code comment if desired.
