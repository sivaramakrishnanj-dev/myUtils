## C3 — AssertionError default branch is sound for sealed hierarchy

- **Location:** `ErrorMapper.categoryOf()` line 46
- **Severity:** Praise
- **Category:** Correctness
- **Spec citation:** Effective Java item 73 (throw exceptions appropriate to the abstraction)
- **Reviewer comment:**
  `YoutubeDownloaderException` is `sealed` with exactly 11 `permits` subtypes. The `instanceof` chain covers all 11. Java's sealed-class guarantee means no external subtype can exist at runtime. The `AssertionError` is unreachable but serves as a compile-time safety net — if a future `permits` addition forgets to update `categoryOf()`, the error fires immediately in tests rather than silently returning a wrong category. Defensive and correct.

## C6 — `internal` category not in AC-5.2's documented set

- **Location:** `ErrorMapper.map()` line 30 — `"Error: internal: "`
- **Severity:** Discussion
- **Category:** Discussion
- **Spec citation:** AC-5.1, AC-5.2
- **Reviewer comment:**
  AC-5.1 says `<category>` is "one of a fixed, documented set (see AC-5.2)". AC-5.2 lists categories for codes 2–70 but does not list `internal` or exit code `1`. The implementer's choice of `(1, "Error: internal: ...")` for non-domain throwables is the right defensive design — POSIX code 1 is the conventional general-error code, and an unexpected throwable genuinely falls outside the domain hierarchy. However, the spec is silent on this path. Consider a future DCR to add `internal` / code `1` to `cli-exit-codes.md § 1` so the contract is complete.
- **Suggested amendment kind:** ac-update (add `internal` / code `1` to AC-5.2 and cli-exit-codes.md § 1)
- **Impact on this review's verdict:** none — this is a spec gap, not a code defect.
