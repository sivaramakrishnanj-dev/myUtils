## C1 — UrlParseException bubbles with picocli generic exit code 1, not exit code 2

- **Location:** `Cli.java:37` — `call()` method
- **Severity:** Minor
- **Category:** Spec-Adherence
- **Spec citation:** AC-5.2 (exit code 2 for argument/URL parse error)
- **Reviewer comment:**
  `UrlParseException.exitCode()` returns `2`, but no `IExitCodeExceptionMapper` is wired in the `CommandLine` setup, so picocli maps any uncaught exception from `call()` to exit code `1` (its default `exitCodeOnExecutionException`). This means an invalid URL currently exits `1`, not `2`. This is **acceptable for T-1.11** because T-1.12 explicitly adds `ErrorMapper` integration to wire the exception → exit-code mapping. Flagging as Minor for traceability — not a defect in this task's scope.
- **Suggested fix:** None needed now. T-1.12 will resolve this.
