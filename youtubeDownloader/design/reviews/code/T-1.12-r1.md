## C1 — Clean try/catch → ErrorMapper → picocli getErr() pipeline

- **Location:** `Cli.call()` in `yt-cli/src/main/java/com/srk/myutils/yd/cli/Cli.java:46-57`
- **Severity:** Praise
- **Category:** Readability
- **Spec citation:** AC-5.1, AC-5.2, AC-5.4, AC-5.5
- **Reviewer comment:**
  The error-handling pipeline is exactly what the spec asks for: `try { ... } catch (Throwable t)` → `ErrorMapper.map(t)` → `err.println(report.message())` → conditional `t.printStackTrace(err)` on `--debug` → `return report.exitCode()`. Clean, linear, no branching complexity. Using picocli's `spec.commandLine().getErr()` instead of `System.err` enables testability — the tester's `StringWriter` capture pattern confirms this works. The `Throwable` catch-all is appropriate here because `ErrorMapper` defensively handles non-domain exceptions with exit code 1 and an `"Error: internal: ..."` message.

## C5 — Minor: `err.println()` relies on picocli flush — correct but implicit

- **Location:** `Cli.call()` line 51: `err.println(report.message())`
- **Severity:** Nit
- **Category:** Reliability
- **Reviewer comment:**
  `PrintWriter` does not auto-flush on `println()` unless constructed with `autoFlush=true`. The output reaches the `StringWriter` in tests because picocli's `CommandLine.execute()` flushes both `out` and `err` writers after `call()` returns. In production, picocli wraps `System.err` in a `PrintWriter(System.err, true)` (auto-flush). So this is correct in both paths. A one-line comment noting the picocli flush contract would help a future reader, but not required.
- **Suggested fix:**
  Optional: add `// picocli flushes getErr() after call() returns` above the `err.println()` line.

## C6 — Minor: `t.printStackTrace(err)` output ordering relative to `err.println()`

- **Location:** `Cli.call()` lines 51-54
- **Severity:** Minor
- **Category:** Correctness
- **Spec citation:** AC-5.5
- **Reviewer comment:**
  Both `err.println(report.message())` and `t.printStackTrace(err)` write to the same `PrintWriter`, so ordering is guaranteed within a single thread. No interleaving risk. The tester's test verifies both strings are present in the output but does not assert ordering (i.e., that the `"Error: args:"` line appears *before* the `"\tat "` lines). In practice, the sequential writes guarantee this, and the test's `contains()` assertions are sufficient for the contract. Noting this as a minor observation — not actionable.
