## C1 — `matches(null)` contract is undocumented

- **Location:** `LanguageCode.java:44` — `matches(LanguageCode other)`
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** 03-data-model.md § 2.2 — spec is silent on null argument to `matches()`
- **Reviewer comment:**
  `matches(null)` throws `NullPointerException` because `other.value` dereferences null. This is acceptable Java convention for a non-nullable value type (Effective Java Item 49 — check parameters for validity; NPE is the standard response for null where null is a programmer error). However, the Javadoc on `matches()` does not document this contract. A one-line `@throws NullPointerException if other is null` makes the contract explicit for downstream consumers (T-4.1 `FormatSelector.selectCaption` will call this).
- **Suggested fix:**
  Add `@throws NullPointerException if other is null` to the `matches()` Javadoc. No code change needed — NPE-on-null is the correct behaviour for this type.

## C2 — Javadoc on `of()` could name the normalization rule

- **Location:** `LanguageCode.java:22` — `of(String raw)`
- **Severity:** Nit
- **Category:** Readability
- **Reviewer comment:**
  The `of()` factory's Javadoc says "Static factory — preferred construction entry point (Effective Java Item 1)." This describes *why* it exists but not *what* it does. The normalization rule (primary subtag lowercased, region subtag preserved) is documented in the record-level Javadoc but not on the method itself. A reader calling `of("EN-US")` benefits from seeing the normalization contract at the call site.
- **Suggested fix:**
  Expand the Javadoc: `/** Parses and normalizes a BCP-47-ish language tag. The primary subtag is lowercased; the region subtag preserves its original case. @throws IllegalArgumentException if raw is null or does not match the BCP-47-ish pattern */`

## C5 — `en-us` (lowercase region) preserved as-is — verify spec intent

- **Location:** `LanguageCodeValidationTest.java:82` — `of_givenLowercaseSubtag_preservesCase`
- **Severity:** Discussion
- **Category:** Spec-Adherence
- **Spec citation:** 03-data-model.md § 2.2 — "Optional region subtag preserves original case."
- **Reviewer comment:**
  The test asserts `LanguageCode.of("en-us").value()` equals `"en-us"` — lowercase region preserved. The spec says "preserves original case", which the implementation honours literally. This means `LanguageCode.of("en-us")` and `LanguageCode.of("en-US")` produce different `value()` strings and are therefore not `equals()`. This is correct per the spec, but worth noting: downstream `FormatSelector.selectCaption` (T-4.1) will need to use `matches()` (not `equals()`) when comparing user-supplied `--lang` against InnerTube caption track language codes, because InnerTube may return `en-US` while the user types `en-us`. The current design handles this correctly via primary-subtag match. No action needed — just flagging for awareness.
