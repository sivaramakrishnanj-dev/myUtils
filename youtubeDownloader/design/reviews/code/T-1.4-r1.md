## C3 — Minor: `Format` Javadoc says `audioSampleRate` is "parsed to int" — clarify the boundary

- **Location:** `Format.java:21` — `@param audioSampleRate sample rate in Hz (audio only; InnerTube sends as string, parsed to int)`
- **Severity:** Minor
- **Category:** Readability
- **Spec citation:** `innertube-player-response.schema.json` (`audioSampleRate` is `type: "string"` on the wire)
- **Reviewer comment:**
  The Javadoc correctly notes that InnerTube sends `audioSampleRate` as a string and the record stores it as `OptionalInt`. However, the phrase "parsed to int" implies this record does the parsing. It doesn't — T-1.7's `PlayerResponseExtractor` (or a Jackson custom deserializer) will handle the string→int conversion. The same applies to `contentLength` (wire: string, record: `Optional<Long>`). A reader encountering this record before `PlayerResponseExtractor` exists might look for parsing logic that isn't here.
- **Suggested fix:**
  Adjust the `@param` to: `@param audioSampleRate sample rate in Hz (audio only; InnerTube wire format is a string — conversion handled by PlayerResponseExtractor)`. Similarly for `contentLength`: `@param contentLength byte length of the stream (optional; InnerTube wire format is a string — conversion handled by PlayerResponseExtractor)`.

## C4 — Minor: `PlayabilityStatus` enum — no `@JsonProperty` or `fromString` for wire-value mapping

- **Location:** `PlayabilityStatus.java` (entire file)
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** `innertube-player-response.schema.json` (`playabilityStatus.status` is a string like `"OK"`, `"UNPLAYABLE"`, etc.), ADR-0004
- **Reviewer comment:**
  The enum values use Java naming (`LIVE_STREAM_OFFLINE`, `AGE_VERIFICATION_REQUIRED`) while the InnerTube wire values use different casing (`LIVE_STREAM_OFFLINE` on the wire is actually `"LIVE_STREAM_OFFLINE"` — happens to match). However, the `UNKNOWN` sentinel requires a fallback path: when Jackson encounters an unrecognized string, it throws by default rather than mapping to `UNKNOWN`. T-1.7's `PlayerResponseExtractor` will need either a `@JsonCreator` on this enum, a custom deserializer, or `DeserializationFeature.READ_UNKNOWN_ENUM_VALUES_USING_DEFAULT_VALUE` with `@JsonEnumDefaultValue` on `UNKNOWN`. This is T-1.7's responsibility, not T-1.4's — the enum itself is correctly shaped. Noting for traceability so the T-1.7 reviewer verifies the UNKNOWN-fallback path is wired.
- **Suggested fix:**
  No code change needed in T-1.4. Consider adding a one-line Javadoc note on `UNKNOWN`: `/** Sentinel for unrecognized wire values — see T-1.7 PlayerResponseExtractor for the fallback deserializer. */`

## C6 — Discussion: Wire-type mismatch for `audioSampleRate` and `contentLength` — T-1.7 must handle

- **Location:** `Format.java:34-35` — `OptionalInt audioSampleRate`, `Optional<Long> contentLength`
- **Severity:** Discussion
- **Category:** Discussion
- **Spec citation:** `innertube-player-response.schema.json` (both fields are `type: "string"` with `pattern: "^[0-9]+$"`)
- **Reviewer comment:**
  The schema documents that InnerTube returns `audioSampleRate` and `contentLength` as base-10 strings (e.g., `"44100"`, `"95000000"`), but the `Format` record stores them as `OptionalInt` and `Optional<Long>` respectively. This is the correct domain representation — callers should not have to parse strings. However, Jackson's default databind cannot deserialize a JSON string `"44100"` into an `OptionalInt` without a custom deserializer or `@JsonDeserialize` annotation. T-1.7's `PlayerResponseExtractor` must provide this conversion. This is not a code defect in T-1.4 — the record's type choices are correct per `03-data-model.md § 2.7`. Flagging for T-1.7 traceability.
- **Suggested amendment kind:** none — this is a T-1.7 implementation concern, not a spec gap.
- **Impact on this review's verdict:** none.
