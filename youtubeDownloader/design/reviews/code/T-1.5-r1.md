## C1 — Clean separation of concerns: transport vs parsing

- **Location:** `InnerTubeClient.java` — class design
- **Severity:** Praise
- **Category:** API-Design
- **Spec citation:** AC-12.3, `02-architecture.md` § 1.2.1
- **Reviewer comment:**
  The class does exactly one thing: issue a single POST and return raw `(httpStatus, body)`. It does not parse the response (that's T-1.7's job), does not decide retry policy (that's T-1.6's job), and does not throw on non-2xx status codes. This is a textbook deep-module design (*A Philosophy of Software Design*, Ousterhout) — the boundary is clean and the responsibilities are minimal. The constructor-injected `OkHttpClient` makes testing trivial without mocking the SUT.

## C3 — `InnerTubeException` extends `RuntimeException` instead of checked exception

- **Location:** `InnerTubeException.java:6`
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** AC-9.4, `04-apis.md` § 3.2.2
- **Reviewer comment:**
  AC-9.4 and `04-apis.md` § 3.2.2 specify that all exceptions in the hierarchy are **checked** (extending `YoutubeDownloaderException`). `InnerTubeException` currently extends `RuntimeException`. The Javadoc correctly notes this is a "minimal stub for T-1.5" and that "T-1.9 will rehome it under `YoutubeDownloaderException`". This is acceptable for T-1.5's scope since T-1.9 is the task that builds the full exception hierarchy. Flagging as Minor so T-1.9 doesn't forget.
- **Suggested fix:**
  No action needed in T-1.5. T-1.9 should change `InnerTubeException extends RuntimeException` → `InnerTubeException extends YoutubeDownloaderException` (or `NetworkException` per the hierarchy in `04-apis.md` § 3.2.2).

## C5 — Factory test uses reflection to extract `httpClient` field

- **Location:** `InnerTubeClientFactoryTest.java:extractHttpClient()` — lines 55–59
- **Severity:** Minor
- **Category:** Testing
- **Reviewer comment:**
  The test uses `Field.setAccessible(true)` to extract the private `httpClient` field. This is fragile — a field rename breaks the test silently at runtime. Acceptable for verifying NFR-pinned timeouts since OkHttp exposes timeout getters on the client, but consider adding a package-private accessor or a `@VisibleForTesting`-annotated method in a future cleanup pass.
- **Suggested fix:**
  Add a package-private `OkHttpClient httpClient()` accessor to `InnerTubeClient` (or accept the reflection cost for now — it's a test-only concern).

## C6 — Thorough error-handling test coverage

- **Location:** `InnerTubeClientErrorHandlingTest.java` — 14 tests
- **Severity:** Praise
- **Category:** Testing
- **Spec citation:** AC-12.4
- **Reviewer comment:**
  The error-handling tests cover HTTP 200, 5xx (500/502/503 parameterized), 404, 403, 429, empty body, whitespace body, `IOException`, `SocketTimeoutException`, `UnknownHostException`, verbatim body return, and large body return. The decision to return `InnerTubeResponse` for non-2xx codes (rather than throwing) is correct — retry logic is T-1.6's responsibility, and the current design gives the retry interceptor full visibility into the HTTP status. Clean test design.

## C7 — SUT is exercised for real in all tests

- **Location:** All 4 test files
- **Severity:** Praise
- **Category:** Testing
- **Spec citation:** Pinned tenet 4 (SUT must not be mocked)
- **Reviewer comment:**
  Every test constructs a real `InnerTubeClient` instance and exercises `fetchPlayer()` end-to-end. The OkHttp interceptor fakes the network layer (the external dependency), not the SUT. This is exactly the right testing discipline — the SUT's request-building, header-setting, body-reading, and exception-wrapping logic all run for real. No Mockito, no PowerMock, no SUT bypass.
