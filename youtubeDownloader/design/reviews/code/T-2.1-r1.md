## C1 — `FormatSelection.video` Javadoc claims null for audio-only but `select()` always populates both

- **Location:** `FormatSelection.java:8` — record Javadoc; `FormatSelector.java:49` — `select()` method
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** AC-2.1 (audio-only mode skips video selection — but that's T-2.10, not T-2.1)
- **Reviewer comment:**
  The `FormatSelection` record's Javadoc says `@param video selected video format (null for audio-only)`, but the only public method `select(List<Format>, int)` always selects both video and audio — it throws `NoMatchingFormatException` if either is absent. There is no `selectAudioOnly()` method yet (that's T-2.10). The Javadoc is forward-looking, which is fine, but callers reading the current API surface may be confused about whether null is a valid state today. Per *Clean Code* (Martin) — comments should describe the code as it is, not as it will be.
- **Suggested fix:**
  Either (a) add a `/** @implNote audio-only selection will be added in T-2.10 */` note to clarify the forward-looking Javadoc, or (b) defer the null-video Javadoc to T-2.10 when the code path actually exists. Author's call — this is Minor.

## C2 — Missing `@Nullable` on `FormatSelection.video` parameter

- **Location:** `FormatSelection.java:13` — record parameter `video`
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** AC-9.1 (stable public API for library embedders)
- **Reviewer comment:**
  If `video` is designed to be nullable for audio-only mode (per the Javadoc), the parameter should carry a `@Nullable` annotation (e.g., `jakarta.annotation.Nullable` or `org.jspecify.annotations.Nullable`) so static analysis tools (NullAway, SpotBugs, IntelliJ inspections) can flag unchecked dereferences in callers. Without it, embedders (P3) have no compile-time signal. Per *Effective Java* item 54 — return empty optionals rather than nulls, or at minimum annotate nullable fields. Since `Format` is a rich object and `Optional<Format>` would be idiomatic, consider whether `Optional<Format> video()` is the better long-term shape. This can wait for T-2.10 when the audio-only path lands.
- **Suggested fix:**
  Add `@Nullable` to the `video` parameter now, or switch to `Optional<Format>` in T-2.10. Either is acceptable; the annotation is the minimal fix.
