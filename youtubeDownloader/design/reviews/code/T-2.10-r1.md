## C1 — `Files.move` with `REPLACE_EXISTING` bypasses overwrite guard when `--force` is false

- **Location:** `YoutubeDownloader.java:170` — `Files.move(audioPart, outputPath, StandardCopyOption.REPLACE_EXISTING)`
- **Severity:** Minor
- **Category:** Correctness
- **Spec citation:** AC-3.6, INV-14
- **Reviewer comment:**
  `assertNotExistsOrForce(outputPath)` runs before the download starts, so the overwrite guard is honoured at the correct point (INV-14 — check before any write). The `REPLACE_EXISTING` flag on the subsequent `Files.move` is therefore safe in practice — the file was confirmed absent (or `--force` was set). However, using `REPLACE_EXISTING` unconditionally is a belt-without-suspenders pattern: if a race condition or future refactor moves the check, the move would silently overwrite. Consider using `REPLACE_EXISTING` only when `request.output().force()` is true, and a plain `Files.move` otherwise, so the filesystem enforces the invariant as a second guard. Not a correctness bug today — the check runs first — but a defensive-coding improvement.
- **Suggested fix:**
  ```java
  StandardCopyOption[] opts = request.output().force()
      ? new StandardCopyOption[]{StandardCopyOption.REPLACE_EXISTING}
      : new StandardCopyOption[0];
  Files.move(audioPart, outputPath, opts);
  ```

## C3 — `DownloadRequest` record has no null-guard on `url`

- **Location:** `DownloadRequest.java:17` — record constructor
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** AC-9.1, Effective Java item 49 (check parameters for validity)
- **Reviewer comment:**
  `DownloadRequest` is a public API surface (AC-9.1). A `null` URL will propagate to `UrlParser.parse(null)` which does throw `UrlParseException`, so the system does fail fast. However, the error message will say "URL is null" from deep inside `UrlParser`, not from the API boundary. A compact null-check in the record's compact constructor would give a clearer error at the point of misuse and is standard practice for public records (Effective Java item 49).
- **Suggested fix:**
  ```java
  public DownloadRequest {
      if (url == null) throw new IllegalArgumentException("url must not be null");
      if (output == null) throw new IllegalArgumentException("output must not be null");
      if (listener == null) throw new IllegalArgumentException("listener must not be null");
  }
  ```

## C4 — `audioFormat.url().substring(0, Math.min(60, ...))` may throw on empty URL

- **Location:** `YoutubeDownloader.java:165` — log statement in `downloadAudioOnly`
- **Severity:** Minor
- **Category:** Reliability
- **Spec citation:** AC-10.2 (INFO on stream download started)
- **Reviewer comment:**
  `Format.url()` returns the CDN URL string. If a format somehow has an empty or null `url` (defensive edge — the format passed cipher filtering, so `url` should be present), `substring` on null would NPE. More practically, the `+ "..."` suffix is always appended even when the URL is shorter than 60 chars, producing misleading output like `https://cdn.example.com/audio...`. Consider using a utility that truncates only when needed.
- **Suggested fix:**
  ```java
  String urlPreview = audioFormat.url().length() > 60
      ? audioFormat.url().substring(0, 60) + "..."
      : audioFormat.url();
  LOGGER.info("Downloading audio stream: itag={} url={}", audioFormat.itag(), urlPreview);
  ```

- **Location:** `YoutubeDownloader.java:50` — `this(urlParser, innerTubeClient, new FormatSelector(), StreamDownloader.create());`
- **Severity:** Minor
- **Category:** Performance
- **Spec citation:** —
- **Reviewer comment:**
  The 2-arg constructor is used by M1 callers (metadata-only). It now eagerly creates a `StreamDownloader` with a production `OkHttpClient` (connection pool, thread pool) that will never be used. The cost is small (one OkHttp client instance), but it's unnecessary work for the metadata-only path.
