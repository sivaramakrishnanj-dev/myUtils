## C2 — Clean `allCipher()` guard handles the no-candidates edge

- **Location:** `FormatSelector.java:79–83` — `allCipher()`
- **Severity:** Praise
- **Category:** Correctness
- **Spec citation:** AC-5.3, AC-5.2 (exit 22 vs exit 30 precedence)
- **Reviewer comment:**
  The `!kind.isEmpty() && kind.stream().allMatch(Format::hasCipher)` guard correctly distinguishes "all candidates are cipher-protected" (→ `CipherRequiredException`, exit 22) from "no candidates of this kind exist at all" (→ `NoMatchingFormatException`, exit 30). Well done.

## C3 — Test 8 uses try-catch instead of AssertJ fluent API

- **Location:** `FormatSelectorCipherBehaviorTest.java:155–165` — `cipherRequiredException_exitCode_is22()`
- **Severity:** Nit
- **Category:** Readability
- **Reviewer comment:**
  The test uses a manual `try/catch` + `Assertions.fail()` pattern to assert `exitCode() == 22`. The rest of the test class uses AssertJ's `assertThatThrownBy()` fluent API. This could be written as:
  ```java
  assertThatThrownBy(() -> selector.select(formats, 1080))
      .isInstanceOf(CipherRequiredException.class)
      .satisfies(e -> assertThat(((CipherRequiredException) e).exitCode()).isEqualTo(22));
  ```
  Not a correctness issue — the current code works and is readable. Author decides.

## C4 — Characterization test duplicates behavior test 6

- **Location:** `FormatSelectorCipherTest.java:18–24` vs `FormatSelectorCipherBehaviorTest.java:120–128`
- **Severity:** Nit
- **Category:** Reuse
- **Reviewer comment:**

This is expected per the spec-driven convention (implementer writes a characterization test, tester writes comprehensive tests independently), so no action needed. Noting for awareness — if test-suite runtime becomes a concern later, the characterization test can be removed.
