## C1 — Resume on 200 (server ignores Range) appends full body to existing partial — file corruption

- **Location:** `StreamDownloader.java:119–123` — `writeBody()` open-option selection
- **Severity:** Minor
- **Category:** Correctness
- **Spec citation:** AC-1.6 (download artifact reaches filesystem as .part)
- **Reviewer comment:**
  When `existingBytes > 0`, the code sends a `Range` header and opens the file with `WRITE, APPEND`. If the CDN responds with `200 OK` instead of `206 Partial Content` (ignoring the Range header), the full response body is appended to the existing partial data, producing a corrupted `.part` file. YouTube CDN almost always honors Range, so this is an edge case — but the fix is a two-line guard: if `existingBytes > 0 && response.code() == 200`, reset `existingBytes = 0` and use `TRUNCATE_EXISTING` instead. Reference: *Release It!* — defensive coding at external boundaries.
- **Suggested fix:**
  After the HTTP status check in `download()`, add:
  ```java
  if (existingBytes > 0 && code == 200) {
      LOGGER.warn("CDN ignored Range header; restarting from byte 0");
      existingBytes = 0;
  }
  ```
  And pass the (possibly reset) `existingBytes` to `writeBody()` and `computeTotalBytes()`. This requires making `existingBytes` non-final or restructuring slightly.

## C2 — `existingFileSize` silently swallows IOException

- **Location:** `StreamDownloader.java:155–160` — `existingFileSize()`
- **Severity:** Minor
- **Category:** Observability
- **Spec citation:** AC-10.1 (SLF4J for all diagnostic output), AC-10.3 (WARN on notables)
- **Reviewer comment:**
  If `Files.size(path)` throws (e.g., permission denied on an existing `.part` file), the method silently returns `0`, causing a fresh download without any log. Per AC-10.3, this is a "notable" event that merits a WARN — the user may not realize their partial file was ignored. Reference: *Clean Code* ch. 7 — don't swallow exceptions silently.
- **Suggested fix:**
  ```java
  } catch (IOException e) {
      LOGGER.warn("Could not read existing .part file size; starting fresh: {}", e.getMessage());
      return 0;
  }
  ```

## C3 — `hostOf` helper swallows all exceptions silently

- **Location:** `StreamDownloader.java:162–168` — `hostOf()`
- **Severity:** Nit
- **Category:** Readability
- **Spec citation:** —
- **Reviewer comment:**
  `hostOf` catches bare `Exception` and falls back to a truncated URL string. This is a log-formatting helper, so the fallback is reasonable, but catching `Exception` is broader than needed — `IllegalArgumentException` from `URI.create()` is the expected failure. Narrowing the catch makes intent clearer. Reference: *Effective Java* item 77 — don't ignore exceptions; item 72 — favor standard exceptions.
- **Suggested fix:**
  Catch `IllegalArgumentException` instead of `Exception`.

## C4 — Well-structured component with clean DI and idiomatic OkHttp usage

- **Location:** `StreamDownloader.java` (entire class)
- **Severity:** Praise
- **Category:** API-Design
- **Reviewer comment:**
  Constructor-injected `OkHttpClient` with a `create()` factory for production defaults is the exact pattern established by `InnerTubeClient` and recommended by ADR-0002. The `ProgressCallback` interface is minimal and well-documented. `try-with-resources` on both `Response` and `OutputStream` satisfies INV-7 cleanly. The 64KB buffer size is a sensible default for streaming I/O. Good work.

- **Location:** `StreamDownloaderBehaviorTest.java` (entire class)
- **Severity:** Praise
- **Category:** Testing
- **Reviewer comment:**
