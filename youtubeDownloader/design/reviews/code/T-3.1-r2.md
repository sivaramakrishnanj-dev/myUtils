## Round 1 open items — disposition

### C1 (Major, Reliability) — Process not destroyed on exception paths — **CLOSED ✓**

- **Round 1 location:** `FfmpegMuxer.java:82–100`
- **Round 2 fix:** Lines 82–98 now wrap the `Process` lifecycle in a try-finally. `process.destroy()` sits in the `finally` block, executing unconditionally after `start()` succeeds — covering the `IOException` from `readLine()`, the `InterruptedException` from `waitFor()`, and the normal-exit path. `Process.destroy()` is a no-op on an already-exited process, so the happy path is safe.
- **Verdict:** Fix is correct and minimal. The structure matches the suggestion from round 1 exactly. No new code paths introduced; existing 18 behaviour tests still pass (confirmed: `mvn test` green, 83 yt-cli + 702 yt-core tests, 0 failures).
