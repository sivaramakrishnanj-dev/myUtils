## C1 — Clean shutdown model: SIGTERM → grace → SIGKILL correctly implemented

- **Location:** `FfmpegMuxer.java:terminateAll()` (lines ~230–248)
- **Severity:** Praise
- **Category:** Correctness
- **Spec citation:** `02-architecture.md` § 5.1 step 2, INV-8
- **Reviewer comment:**
  The `terminateAll()` method follows the spec's shutdown model precisely: `destroy()` (SIGTERM) → `waitFor(5, SECONDS)` → `destroyForcibly()` (SIGKILL) if still alive. The `InterruptedException` handler correctly re-interrupts the thread and force-kills the process, preventing a hung shutdown hook. This is exactly the pattern *Release It!* recommends for child-process lifecycle management.

## C2 — Static initializer for shutdown hook is the right choice

- **Location:** `FfmpegMuxer.java` — `static { Runtime.getRuntime().addShutdownHook(...) }`
- **Severity:** Praise
- **Category:** Reliability
- **Spec citation:** `02-architecture.md` § 5.1 step 1
- **Reviewer comment:**
  Registering the shutdown hook in a static initializer guarantees it runs exactly once on class load, regardless of how many `FfmpegMuxer` instances are created. This avoids the double-registration bug that would occur if the hook were registered in the constructor. The hook thread is named `"ffmpeg-shutdown"` — good for thread-dump readability.

## C3 — ConcurrentHashMap.newKeySet() is the correct concurrent collection

- **Location:** `FfmpegMuxer.java:LIVE_PROCESSES` declaration
- **Severity:** Praise
- **Category:** Correctness
- **Spec citation:** INV-8
- **Reviewer comment:**
  `ConcurrentHashMap.newKeySet()` provides thread-safe add/remove/iterate without external synchronization. The shutdown hook iterates the set while `mux()`/`transcodeMp3()` may be removing from it on the main thread — `ConcurrentHashMap`'s weakly-consistent iterator handles this correctly without `ConcurrentModificationException`. The tester's test 7 (`liveProcesses_givenConcurrentAddRemove_noConcurrentModificationException`) explicitly verifies this property.

## C4 — Process registration in finally block ensures deregistration on all exit paths

- **Location:** `FfmpegMuxer.java:mux()` and `transcodeMp3()` — `LIVE_PROCESSES.add(process)` before `waitFor`, `LIVE_PROCESSES.remove(process)` in `finally`
- **Severity:** Minor
- **Category:** Correctness
- **Spec citation:** INV-8
- **Reviewer comment:**
  The process is added to `LIVE_PROCESSES` immediately after `ProcessBuilder.start()` and removed in the `finally` block. This is correct — the process is tracked for the entire duration it could be alive. However, the `add` happens *before* the `try` block that contains the `finally`. If an exception were thrown between `add` and the `try` entry (theoretically impossible in the current code since `add` is the statement immediately before `try`), the process would leak from the set. This is a non-issue in practice because `ConcurrentHashMap.add()` cannot throw, and the `try` immediately follows. Noting for completeness only.
- **Suggested fix:**
  No change needed. The current structure is safe.

## C5 — `liveProcesses()` returns defensive unmodifiable view

- **Location:** `FfmpegMuxer.java:liveProcesses()`
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** — (test-support API, not spec-driven)
- **Reviewer comment:**
  `Collections.unmodifiableSet(LIVE_PROCESSES)` wraps the live backing set — callers cannot mutate it, but they see a live view (reads reflect concurrent changes). For test-only package-private access this is fine. A snapshot (`Set.copyOf(LIVE_PROCESSES)`) would be safer for a public API, but this is deliberately package-private for testability. Acceptable as-is.

## C6 — Tester coverage is thorough: 10 tests covering all shutdown facets

- **Location:** `FfmpegMuxerShutdownBehaviorTest.java`
- **Severity:** Praise
- **Category:** Testing
- **Spec citation:** INV-8, `02-architecture.md` § 5
- **Reviewer comment:**
  The tester covers: add/remove/view lifecycle (tests 1–3), empty-set no-op (test 4), kill-within-grace-period timing assertion (test 5), mux/transcode deregistration on success (tests 6–7), multi-instance shared set (test 8), already-exited process skip (test 9), and concurrent-modification safety (test 10). The `@AfterEach` cleanup ensures no leaked processes across tests. The `@DisabledOnOs(OS.WINDOWS)` annotations are correct — `sleep` and POSIX signals are not available on Windows. Good discipline.

## C7 — Characterization test directly invokes `terminateAll()` — acceptable given JVM constraint

- **Location:** `FfmpegMuxerShutdownTest.java`
- **Severity:** Nit
- **Category:** Testing
- **Reviewer comment:**
  The characterization test cannot fire the actual JVM shutdown hook (calling `Runtime.halt()` or `System.exit()` in a test would kill the test runner). Directly invoking `terminateAll()` is the pragmatic alternative and is well-documented in the test's Javadoc. The `finally` block cleans up the process and deregisters it from `LIVE_PROCESSES`. Clean.
