## C1 — Flow C routing guard correctly placed

- **Location:** `YoutubeDownloader.java:162–164`
- **Severity:** Praise
- **Category:** Spec-Adherence
- **Spec citation:** 02-architecture.md § 2.3, state-machine.md `SELECTING_FORMATS --> DOWNLOADING_CAPTIONS: transcriptOnly mode`
- **Reviewer comment:**
  The guard `request.transcript() && !request.audioOnly()` is placed before the `audioOnly()` check, matching the state-machine's Flow C trigger exactly. This ensures `--transcript --audio-only` correctly routes to Flow B (with transcript as a side-effect), while `--transcript` alone routes to Flow C. The ordering is deliberate and correct per 04-apis.md § 3.1.2: `--video` is implicitly true only when neither `--audio-only` nor `--transcript`/`--thumbnail` alone is given.

## C2 — NetworkException propagation discipline in Flow C

- **Location:** `YoutubeDownloader.java:252–256` (`downloadTranscriptOnly`, catch block)

- **Category:** Spec-Adherence
- **Spec citation:** state-machine.md: `DOWNLOADING_CAPTIONS --> TERMINATED: caption fetch failed AND transcript is the only output → exit 10 or 40`

## C4 — .srt/.txt path derivation uses OutputWriter consistently

- **Location:** `YoutubeDownloader.java:261–265`
- **Severity:** Minor
- **Category:** Readability
- **Spec citation:** AC-6.2 — "write the transcript to disk in two files alongside the video (or audio, or on its own)"
- **Reviewer comment:**
  The path derivation `basePath = outputWriter.deriveOutputPath(player.videoDetails(), "srt")` then `txtPath = basePath.resolveSibling(stripExtension(basePath).getFileName() + ".txt")` works correctly but is slightly indirect — `basePath` is already the `.srt` path, then `stripExtension` removes `.srt` to re-add `.txt`. - **Suggested fix:** No change needed. Noting for awareness only.
