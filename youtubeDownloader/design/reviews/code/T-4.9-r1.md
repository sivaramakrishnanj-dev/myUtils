## C4 — Consider a builder or named-factory pattern for DownloadRequest

- **Location:** `yt-core/src/main/java/com/srk/myutils/yd/core/DownloadRequest.java`
- **Severity:** Minor
- **Category:** API-Design
- **Spec citation:** — (general maintainability, *Effective Java* item 2)
- **Reviewer comment:**
  `DownloadRequest` is now a 12-parameter record. Each new boolean flag (thumbnail, transcript, noAsr, debug) adds another positional `false` to every call site — 13 existing tests needed mechanical updates. A builder pattern would make future flag additions (M5 flags, any post-MVP additions) zero-cost at existing call sites. This is not blocking because the current code is correct and the record is immutable, but the maintenance cost is compounding.
- **Suggested fix:**
  Introduce a `DownloadRequest.Builder` (or use the existing `audioOnly(...)` factory as a template for more named factories) in a future task. Not required for T-4.9.
