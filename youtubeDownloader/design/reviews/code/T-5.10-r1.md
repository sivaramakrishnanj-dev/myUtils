## C1 — macOS x86_64 not covered in CI matrix

- **Location:** `.github/workflows/ci.yml:smoke-test.matrix`
- **Severity:** Minor
- **Category:** Spec-Adherence
- **Spec citation:** NFR-SUPPORTED-OS — "macOS 13+ (x86_64, aarch64)"
- **Reviewer comment:**
  The CI smoke-test matrix includes `macos-14` (Apple Silicon / aarch64) but not a macOS x86_64 runner (e.g., `macos-13`). NFR-SUPPORTED-OS lists both architectures. Since the fat-jar is pure Java (no native code), the risk is low — JVM portability covers this. However, the spec explicitly names both. The manual checklist in `SMOKE_TESTS.md` covers it implicitly ("macOS 13+ Apple Silicon / Intel") which is acceptable documentation.
- **Suggested fix:**
  Either add `macos-13` (Intel) to the CI matrix, or add a one-line note in `SMOKE_TESTS.md` § "OS-Specific Notes > macOS" stating that x86_64 is verified via Rosetta 2 on `macos-14` or manually on Intel hardware. No blocker — the pure-Java nature makes this a documentation gap, not a correctness gap.

## C2 — Linux aarch64 CI coverage is conditional / undocumented fallback

- **Location:** `.github/workflows/ci.yml` (absent from matrix) and `SMOKE_TESTS.md:§ Linux aarch64`
- **Severity:** Minor
- **Category:** Spec-Adherence
- **Spec citation:** NFR-SUPPORTED-OS — "Linux (x86_64, aarch64) with glibc 2.31+"
- **Reviewer comment:**
  The CI matrix does not include `ubuntu-22.04-arm`. `SMOKE_TESTS.md` documents that it "is included when the `ubuntu-22.04-arm` runner is available" and suggests manual verification or QEMU as fallback. This is a pragmatic choice given GitHub Actions' limited ARM runner availability, but the fallback procedure is vague — no concrete QEMU command or cross-compilation step is given.
- **Suggested fix:**
  Add a brief "Fallback verification" sub-section under "Linux aarch64" in `SMOKE_TESTS.md` with a concrete command, e.g.:
  ```bash
  # Via Docker + QEMU (requires docker with binfmt_misc registered):
  docker run --rm --platform linux/arm64 eclipse-temurin:17-jdk bash -c \
    "java -jar /mnt/youtube-downloader-1.0.0.jar --version"
  ```
  This makes the fallback actionable rather than aspirational.

## C3 — Smoke script checks 6 assertions but only 4 exercise exit codes from cli-exit-codes.md

- **Location:** `scripts/smoke-test.sh:20-35`
- **Severity:** Minor
- **Category:** Testing
- **Spec citation:** `cli-exit-codes.md` § 1 — codes 0, 2 tested; codes 10, 11, 20, 21, 22, 30, 40, 50, 60, 70 not exercised
- **Reviewer comment:**
  The smoke test validates exit codes `0` (--version, --help) and `2` (no-args, invalid URL). This is appropriate for a *smoke* test — it confirms the jar boots and the CLI parser works. The remaining exit codes require network or specific video states and belong in the integration suite (T-5.4), not the smoke script. The scope is correct for a smoke test's purpose.
- **Suggested fix:**
  None needed — this is an observation, not a defect. The task's scope is "smoke-test matrix" not "exhaustive exit-code matrix". T-5.4 covers the deeper paths.

## C4 — `set -euo pipefail` combined with `|| actual=$?` pattern is correct

- **Location:** `scripts/smoke-test.sh:5,14`
- **Severity:** Praise
- **Category:** Correctness
- **Reviewer comment:**
  The script uses `set -euo pipefail` for strictness but correctly captures non-zero exits via `"$@" >/dev/null 2>&1 || actual=$?` — the `||` prevents `set -e` from aborting on expected non-zero exits. Clean shell idiom.

## C5 — CI workflow structure: `needs: build` ensures smoke runs only after verify passes

- **Location:** `.github/workflows/ci.yml:smoke-test.needs`
- **Severity:** Praise
- **Category:** Reliability
- **Reviewer comment:**
  The `smoke-test` job depends on `build` completing first. This means smoke tests only run against a jar that already passed `mvn clean verify` (unit tests + JaCoCo gate). Good sequencing — avoids wasting runner minutes on a broken build.

## C6 — `fail-fast: false` on smoke matrix is appropriate

- **Location:** `.github/workflows/ci.yml:smoke-test.strategy.fail-fast`
- **Severity:** Praise
- **Category:** Reliability
- **Reviewer comment:**
  `fail-fast: false` ensures both OS legs complete even if one fails. For a cross-platform smoke test, you want to see *all* failures, not just the first. Correct choice.

## C8 — NFR-MIN-FFMPEG-VERSION mismatch in SMOKE_TESTS.md prerequisites

- **Location:** `SMOKE_TESTS.md:§ Prerequisites` — "ffmpeg 6+"
- **Severity:** Minor
- **Category:** Spec-Adherence
- **Spec citation:** NFR-MIN-FFMPEG-VERSION = 4.0
- **Reviewer comment:**
  The prerequisites section states "ffmpeg 6+" but the spec pins `NFR-MIN-FFMPEG-VERSION = 4.0`. The smoke test itself doesn't check ffmpeg version (it only runs `--version` and `--help` which don't invoke ffmpeg per AC-13.5), so this is a documentation inaccuracy rather than a functional bug. However, it could mislead a tester into thinking ffmpeg 4.x is insufficient.
- **Suggested fix:**
  Change "ffmpeg 6+" to "ffmpeg 4.0+" (per `NFR-MIN-FFMPEG-VERSION`) or "ffmpeg (any version ≥ 4.0; 6+ recommended for best codec support)".
