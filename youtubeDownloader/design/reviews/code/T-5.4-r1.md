## C6 — Minor: `invalidUrlProducesNonZeroExit` is redundant with `invalidUrl_exitsWithCode2`

- **Location:** `YoutubeDownloaderIT.java:48–56`
- **Severity:** Minor
- **Category:** Readability
- **Reviewer comment:**
  `invalidUrlProducesNonZeroExit()` asserts `exitValue().isNotZero()` on the same input as `invalidUrl_exitsWithCode2()` which asserts `exitValue() == 2`. The weaker assertion is fully subsumed by the stronger one. Not harmful, but adds maintenance surface without additional confidence.
- **Suggested fix:**
  Consider removing `invalidUrlProducesNonZeroExit` or converting it to test a *different* invalid-input category (e.g., no-argument invocation → CT-EXIT-2a, or unknown flag → CT-EXIT-2c) to cover more contract tests.

## C7 — Minor: `redirectErrorStream(true)` in `helpExitsZero` discards stderr distinction

- **Location:** `YoutubeDownloaderIT.java:30–36`
- **Severity:** Minor
- **Category:** Testing
- **Spec citation:** AC-5.1 (error line to stderr)
- **Reviewer comment:**
  `helpExitsZero()` and `versionExitsZero()` use `redirectErrorStream(true)`, merging stdout and stderr. This is fine for asserting exit code, but if a future assertion needs to verify that `--help` produces no stderr output (AC-5.4: no stack trace on normal paths), the merged stream would mask it. The later tests (`invalidUrl_exitsWithCode2`, `debugWithInvalidUrl_showsStackTrace`) correctly keep streams separate.
- **Suggested fix:**
  Low priority — acceptable as-is for M5. If you add content assertions to the help/version tests later, split the streams then.

## C8 — Discussion: CT-EXIT-2a and CT-EXIT-2c not yet covered

- **Location:** design spec — `contract-tests.md` § 4
- **Severity:** Discussion
- **Category:** Discussion
- **Spec citation:** CT-EXIT-2a (no URL argument → exit 2), CT-EXIT-2c (unknown flag → exit 2)
- **Reviewer comment:**
  The task row says "4 canonical URLs" but the contract-tests table lists 8 integration-level exit-code scenarios (CT-EXIT-0, 2a, 2b, 2c, 10, 50, 60a, 60b). The current suite covers CT-EXIT-2b explicitly and exercises --help/--version (exit 0). CT-EXIT-2a (no argument) and CT-EXIT-2c (unknown flag) are trivial to add and would strengthen the suite. CT-EXIT-10/50/60a/60b require more infrastructure (proxy, pre-existing file, bad ffmpeg path) and may belong in later tasks.
- **Suggested amendment kind:** ac-update (clarify which CT-EXIT-* are in-scope for T-5.4 vs T-5.10)
- **Impact on this review's verdict:** none — this is a scope-clarification observation, not a code defect.
