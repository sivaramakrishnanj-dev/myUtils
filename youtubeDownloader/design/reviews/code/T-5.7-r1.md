## C2 — Integration tests gated on main push only

- **Location:** `.github/workflows/ci.yml:18` — `integration.if`
- **Severity:** Praise
- **Category:** Reliability
- **Reviewer comment:**
  Integration tests are correctly gated behind `github.event_name == 'push' && github.ref == 'refs/heads/main'`. This avoids burning network-dependent integration tests on every PR push (which would be flaky and slow), while still running them on merge to main. Matches the project's integration-test philosophy (opt-in, online, smoke-testing against reality per `05-operations.md` § 4.2).

## C3 — Integration job runs on single OS only

- **Location:** `.github/workflows/ci.yml:19` — `integration.runs-on: ubuntu-latest`
- **Severity:** Minor
- **Category:** Reliability
- **Spec citation:** `NFR-SUPPORTED-OS`
- **Reviewer comment:**
  The integration job runs only on `ubuntu-latest`, not on the full matrix. Since integration tests exercise real YouTube network calls, running them on both OSes would double network load for minimal additional signal (the HTTP client behaves identically across platforms). This is a reasonable trade-off. However, if ffmpeg-dependent integration tests are added later (M3 paths), macOS ffmpeg behavior differences (Risk R-4) would be missed. Flagging as Minor — acceptable for MVP; revisit when T-5.10 lands.
- **Suggested fix:**
  Consider adding a comment in the workflow noting the single-OS choice is intentional, or add macOS to the integration matrix when ffmpeg integration tests exist.

## C6 — No `permissions` block in workflow

- **Location:** `.github/workflows/ci.yml` (top-level)
- **Severity:** Minor
- **Category:** Security
- **Spec citation:** AWS Well-Architected Security pillar — least privilege
- **Reviewer comment:**
  The workflow does not declare a top-level `permissions:` block. GitHub Actions defaults to `contents: read` for pull_request triggers but broader permissions for push triggers. Adding an explicit `permissions: contents: read` at the top level follows the principle of least privilege and prevents accidental token exposure if a dependency or step is compromised. Reference: GitHub Actions security hardening guide.
- **Suggested fix:**
  Add at the top level (after `on:`):
  ```yaml
  permissions:
    contents: read
  ```
